# Development priorities

SwapCtx remains a Windows-first Rust CLI with local SQLite persistence, deliberate
memory capture and explicit provider sharing. No mandatory service, daemon or
subscription is planned. This roadmap records priorities, not delivery dates.

## Before the first public preview

- Integrate the unified native/intelligence foundation after exact-revision Windows,
  Linux, advisory and fresh portable-producer checks pass.
- Keep handoff preview/apply contracts aligned and memory health diagnostics useful.
  Exact duplicate candidates are reviewable; no automatic knowledge merging occurs.
- Verify a private security reporting route and record the signing or unsigned-preview
  trust decision. Do not invent a contact address or publisher identity.
- Repeat recipient acceptance for the final binary on an independent Windows machine.
  Preserve executable, archive and installer hashes with the source revision.
- Prepare the release notes and trusted installation instructions. Repository
  visibility, public release and external asset distribution require founder approval.

## Next engineering evidence

- Evaluate exact installed Codex and Claude versions with separately authorized
  live sessions. Distinguish hook loading, local preparation, actual receipt and
  observed adherence. Synthetic tests alone do not certify provider compatibility.
- Improve audit/explanation guidance where real developer workflows reveal friction.
  Preserve versioned JSON, legacy-store recovery and explicit consent.
- Add new provider adapters only around the existing context protocol; keep provider
  process and authentication details outside the memory engine.

Track acceptance work in the [preview milestone](https://github.com/rehnx/SwapCtx/milestone/1).
